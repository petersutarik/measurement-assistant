# Measurement Assistant

AI-powered SaaS for dataLayer implementation documentation and marketing measurement plans.

## Tech Stack

- **Framework:** Next.js 15 (App Router) with TypeScript
- **Styling:** Tailwind CSS v4 + shadcn/ui
- **Database:** PostgreSQL (Supabase) with Drizzle ORM
- **Auth:** Supabase Auth (`@supabase/ssr`)
- **Validation:** Zod

## Project Structure

```
src/
  app/           — Next.js App Router pages and layouts
    api/         — REST API routes
  components/
    ui/          — shadcn/ui components
  lib/
    db/
      schema/    — Drizzle schema files (_helpers, tenant, spec, destinations, etc.)
    supabase/    — Supabase client helpers (server.ts, client.ts)
    utils.ts     — shadcn/ui utility (cn)
    validators/  — Zod validation schemas
  middleware.ts  — Supabase auth session refresh
  types/         — TypeScript types (derived from Drizzle)
supabase/
  migrations/    — SQL migrations (generated by drizzle-kit)
```

## Commands

```bash
npm run dev          # Start dev server (Turbopack)
npm run build        # Production build
npm run lint         # ESLint
npm run format       # Prettier
npm test             # Run tests (Vitest)
npm run test:watch   # Watch mode tests
npm run db:generate  # Generate migrations from schema
npm run db:migrate   # Run migrations
npm run db:push      # Push schema directly (dev)
npm run db:studio    # Open Drizzle Studio

# Supabase
supabase start       # Start local Supabase (Postgres, Auth, Storage)
supabase stop        # Stop local Supabase
supabase db reset    # Reset local DB and re-run migrations
supabase status      # Show local Supabase URLs and keys
```

## Conventions

- Use `@/` import alias for all project imports
- Drizzle schema files go in `src/lib/db/schema/` and are re-exported from `index.ts`
- Zod validators go in `src/lib/validators/`
- Types derived from Drizzle use `InferSelectModel` in `src/types/`
- Use shadcn/ui components via `npx shadcn@latest add <component>`
- Supabase client: use `src/lib/supabase/server.ts` in Server Components/Actions, `src/lib/supabase/client.ts` in Client Components
- Two clients coexist: Drizzle for typed queries, Supabase client for auth/realtime/storage
- Schema enums and timestamps mixin are in `src/lib/db/schema/_helpers.ts`
- Environment variables: copy `.env.example` to `.env.local`, then run `supabase start` and fill in keys from `supabase status`
- Server actions live alongside their pages (e.g., `src/app/(app)/projects/actions.ts`)
- All server actions use `requireUserContext()` from `src/lib/auth/user-context.ts` for auth + tenant scoping
- shadcn/ui v4 uses `render` prop (not `asChild`) for trigger composition — e.g., `<DialogTrigger render={<Button />} />`
- Tests: co-locate with source as `*.test.ts`, use Vitest
- Use `slugify()` from `src/lib/slugify.ts` for generating slugs from names
- **Drizzle schema sync:** After any change to `src/lib/db/schema/`, run `DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:54322/postgres" npx drizzle-kit push` to push the schema to the local dev database
- **API routes** go in `src/app/api/v1/` with Bearer token auth via `requireApiAuth()` from `src/lib/api/auth.ts`
- API response helpers in `src/lib/api/response.ts` (`ok`, `created`, `notFound`, `validationError`, etc.)
- Shared data cloning logic in `src/lib/api/clone.ts` (used by both server actions and API routes)
- API docs: `docs/API.md`
